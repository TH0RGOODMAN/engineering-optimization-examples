# 双机加权完工时间：模型与验证

版本v0.1.0；检查日期2026-11-09；本机Node.js v24.22.1及Chromium。

## 约定

有n个订单（1≤n≤8）和两台无关联机器。订单i在机器k上的加工时间pᵢₖ是1–20整数，权重wᵢ为1–10整数。时间单位为合成单位，权重为无量纲优先程度。每个订单在一台机器上连续加工一次，所有订单从0时刻可用，无准备、切换或等待设备成本，同机不重叠。

完工时间Cᵢ从共同0时刻计算。目标min ΣwᵢCᵢ；总工期max Cᵢ与完工时间总和ΣCᵢ只作补充指标。没有交期，因此未计算拖期。

默认数据为新造合成例子：A(3,8;2)、B(8,3;1)、C(4,6;4)、D(6,2;2)、E(2,5;5)、F(5,4;3)，括号内为两机工时和权重。

## 直观派单基线

按输入顺序访问订单，把它追加到当前“机器已有负荷+该订单工时”较小的机器，平局选机器1。此基线没有按权重优先，也不向前看；它不是对所有调度启发式的代表性评测。

默认基线：机器1 A→C→E，机器2 B→D→F，ΣwC=119，总工期9。

## 精确算法

每个订单有两种机器选择，穷举2ⁿ种分配。给定分配后，对每台机器的订单按pᵢₖ/wᵢ非降序排列；实现用整数交叉乘积比较，避免浮点比值误差。

证明：考虑从时间t起的相邻订单i和j。

- i→j的相关代价：wᵢ(t+pᵢ)+wⱼ(t+pᵢ+pⱼ)。
- j→i的相关代价：wⱼ(t+pⱼ)+wᵢ(t+pⱼ+pᵢ)。
- 前者减后者为wⱼpᵢ−wᵢpⱼ。当pᵢ/wᵢ≤pⱼ/wⱼ，i在前不会更差。

重复交换倒序相邻项即可得到最优顺序。所有权重/工时为正，所有订单同时可用，加入空闲只会延后完工，所以各机从0开始连续加工。每种分配已经采用其最优顺序，取目标最小者就是当前模型的全局最优。

比值相同按订单ID排序，分配同目标保留枚举首先遇到的方案；不声称最优安排唯一或对总工期进行第二目标优化。

默认最优：机器1 E→C→A，机器2 D→F→B，ΣwC=83，总工期9。

## 实际测试

`node --test`：8组通过。

1. 三个固定预设，与独立全排列/分割法比较最优目标。
2. 固定种子9647的60组1–6单随机工时/权重，同样独立比较。参考算法枚举订单全排列和两机分割点，不调用Smith规则或生产排程函数。
3. 单订单、同工时/权重、确定性平局。
4. 可复核的目标取舍例：A(3,4;6)、B(2,6;5)、C(1,7;3)、D(6,7;4)。基线ΣwC=89/总工期7，精确最优78/总工期9；降低当前目标并不保证更早全部结束。
5. 8单最大工时/权重边界，共256种分配，两机各4单时ΣwC=4000，总工期80。
6. 非法数据拒绝：订单数、ID重复/格式、权重/工时的零、超限、非整数、非数字。
7. 输入不变、逆序输入的最优目标一致、JSON导出后重新计算完全一致。
8. 本机服务只提供公开清单，正常网页/模块/HEAD通过，Git、环境文件、开发脚本、任意本机路径和非GET/HEAD请求不可用。

输出逐单检查机器、加工长度、开始/完工相接、每单恰好一次，以及目标/总工期/完工时间总和重新求和。测试支持本模型内的正确性，不代表本人进行真人实验。
